# DeMoL README Tone Anchor

Register: friendly-academic. Nix-dry, declarative, technical. No first-person plural ("we"). No hedging ("we hope", "we believe"). No sign-offs. No em-dash stacks. No ALL-CAPS emphasis. Present tense.

## Pass examples (target voice)

1. > "DeMoL is a textX-based DSL for declarative IoT device modeling with hardware-aware semantic validation."

2. > "A device model is a text file in `.dev` format: a single artifact that captures the board, peripherals, connections, communication, sampling, constraints, and alerts."

3. > "Generated code is reproducible: the same `.dev` model produces the same RPi Python and RIOT C outputs across runs and across machines."

## Fail examples (the wrong voice)

1. > "Welcome to DeMoL, the revolutionary platform that's changing the way researchers think about IoT."  ❌ chatty + hype

2. > "We hope DeMoL might be useful for your research and we'd love to hear your feedback."  ❌ hedging + sycophantic

3. > "Imagine a world where you can model your entire IoT device in minutes, without ever writing a single line of code."  ❌ setup-to-pitch + absolute claim

## How to interpret

- **Declarative**, not persuasive. State what DeMoL *is*, not what it *could do for you*.
- **Concrete**, not abstract. Name the file format, the validation rule, the generated target.
- **Single voice**, not "we". DeMoL or "the project" as subject.
- **One ask per sentence**, not stacked claims.
